# S01：核心契约与工程质量体系

## 阶段目标

建立后续所有模型、算子、量化、Backend、Serving 和 Benchmark 共同依赖的稳定 Contract、注册机制、测试金字塔、CI 与可复现规范，使模块可以独立开发而不产生循环依赖。

## 体现的知识与技能

软件架构、SOLID、依赖倒置、高内聚低耦合、Schema、Python/C++ 工程、测试、CI/CD、配置管理和 API 演进。

## 输入

- S00 的可信 inventory、Evidence Ledger 和可运行 smoke。
- 顶层架构中的 C1–C7 Contract。
- 当前 `configs/`、`benchmarks/schemas/`、`hqsb/benchmark/`。

## 执行步骤

1. 为 `core` 写模块 ownership 和依赖规则，配置静态依赖检查，禁止 `core` 导入具体 backend。
2. 定义并版本化 ModelArtifact、WorkloadSpec、OperatorSpec、BackendCapability、QuantArtifact、BenchmarkResult、TraceEvent schema。
3. 明确 schema 向后兼容、迁移和拒绝策略；提供 legacy golden/result migration。
4. 建立统一 config loader：默认值、环境覆盖、CLI 覆盖、类型检查、未知字段拒绝和 config hash。
5. 建立 registry/plugin：Backend、Operator、Quantizer、Monitor、Reporter 注册；重复名称、版本冲突和能力缺失要显式失败。
6. 建立统一 error taxonomy、exit code、structured logging 和 run ID/trace ID。
7. 建立 Python packaging、可选依赖组与锁定策略；区分 CPU、CUDA、Jetson、Ascend、serving、dev。
8. 重构 benchmark，使其只依赖 Backend interface 与 Contract，不导入具体 Qwen loader。
9. 建立测试目录和 marker：unit/property/correctness/integration/e2e/performance/hardware。
10. 配置格式化、lint、类型检查、C++/CUDA format、license/secret/dependency 检查。
11. 建立 CPU PR CI；GPU/NPU 任务定义为 self-hosted/nightly，产物带环境与 Commit。
12. 建立 ADR 模板、实验记录模板、优化日志模板和阶段 handoff 模板。
13. 建立文档自动检查：坏链接、命令 smoke、schema examples 和版本漂移。
14. 为 Contract 写 reference examples，确保第三方 Coding Agent 可据此实现新 backend。

## 输出与产出

- `hqsb/core` 的稳定 Contract、config、registry、errors。
- 版本化 JSON/YAML schema 与 migration 工具。
- Python package/依赖组、开发命令和 CI 配置。
- 测试金字塔、ADR/实验/handoff 模板。
- 架构依赖图和模块 ownership 文档。

## 测试标准

- Schema：有效、缺字段、未知字段、旧版本迁移、未来版本拒绝。
- Config：默认/文件/环境/CLI precedence 与 hash 稳定性。
- Registry：注册、发现、冲突、卸载、能力不足。
- Error/log：每个公共失败路径有稳定错误类型和 trace/run ID。
- Dependency：检测循环导入和 core→concrete backend 违规。
- Packaging：干净虚拟环境可安装 CPU 最小包，不拉取所有硬件依赖。

## 验收通过标准

- CPU CI 全部通过且不需要模型权重/GPU。
- 一个 dummy backend 能仅依据 Contract 完成注册、运行和结果写出。
- 现有 model-core、golden 和 RMSNorm metadata 已迁移到新 schema。
- 新模块的接入点、错误和测试要求没有歧义。

## 明确不做

不实现真实 runtime 或新 kernel；本阶段只提供稳定地基和 reference/dummy 实现。

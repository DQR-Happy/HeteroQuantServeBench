# S05：量化与低精度推理

## 阶段目标

建立 QuantLab：从量化算法、模型制品和数值质量一直贯通到低比特 Kernel、模型推理与硬件收益，系统比较 RTN、GPTQ/AWQ、SmoothQuant 等方法，而不是只生成权重文件。

## 体现的知识与技能

数值表示、PTQ/QAT、校准、误差分析、INT8/INT4/FP8、模型压缩、Quant GEMM/dequant fusion、精度—性能—内存权衡。

## 输入

- S01 Model/Quant/Result Contract。
- S02 FP16 reference、golden、workload 和质量/性能基线。
- S03/S04 operator framework、GEMM/library 能力。
- 固定校准集和独立评测集。

## 执行步骤

1. 定义量化语义与 artifact：bit、granularity、group size、symmetric、scale/zero-point、packing/layout、calibration、kernel compatibility。
2. 自实现 RTN：INT8/INT4，per-channel/per-group，对称/非对称；保留 FP32 reference 和可逆 debug path。
3. 实现 calibration pipeline、样本版本和统计；训练校准集与最终评测集隔离。
4. 集成 GPTQ、AWQ、SmoothQuant；adapter 只负责转换为统一 QuantArtifact，不掩盖第三方行为。
5. 可选扩展 LLM.int8、QAT/LSQ、FP8、KV Cache quantization；每项独立 capability。
6. 建立 tensor/operator/model 三层误差：max/mean/RMSE/cosine、logit/token、PPL/小型任务质量。
7. 实现或接入 W8A8、W4A16/W4A8 的 dequant/linear 路径；优先成熟 GEMM 库和合理 layout。
8. 研究至少一个融合：dequant+GEMM epilogue、RMSNorm+Quantize 或 KV quant/dequant。
9. 在 Jetson、云端 GPU 和支持的 Ascend backend 上运行统一矩阵，检测硬件原生低精度支持。
10. 报告模型大小、load time、peak memory、TTFT、TPOT、TPS、功耗、能耗和质量。
11. 分析 weight packing、dequant overhead、kernel availability 和 memory bandwidth，解释压缩率与 speedup 差异。
12. 建立量化 artifact 兼容与迁移测试，拒绝 layout/kernel 不匹配的静默执行。

## 输出与产出

- `hqsb/quant` 的基础算法与第三方 adapter。
- 版本化 QuantArtifact、calibration/evaluation manifest。
- 低比特/融合 kernel 或 library integration。
- accuracy-memory-performance-energy Pareto report。
- 各方法 limitations 与硬件支持矩阵。

## 测试标准

- 量化/反量化 tensor property test；scale/zero-point/packing 边界。
- 同模型 FP16 vs quant 的 logit/token/PPL/任务指标。
- Artifact hash、schema、round-trip、版本和非法组合测试。
- Kernel correctness 覆盖 K/M/N、group size、alignment 和尾块。
- 性能结果必须包含量化时间与推理时间，不能混淆离线/在线成本。

## 验收通过标准

- 自实现 RTN 与至少两种工业方法可统一评估。
- 至少一个低比特路径在目标硬件有可解释的模型级收益；无收益也需有硬件/软件证据。
- 能回答量化误差、内存、带宽、计算和 Runtime 支持的完整因果链。

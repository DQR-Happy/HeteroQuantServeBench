# S00：现状审计与基线恢复

## 阶段目标

把当前仓库从“文档与 Git tree 不一致”恢复为可信 Source of Truth。阶段结束后，任何开发者都能知道什么已实现、什么仅历史运行过、什么尚未开始，并能执行最小 CUDA 和 Qwen model-core smoke 流程。

## 体现的知识与技能

Git/版本管理、Linux、CMake、Python packaging、依赖管理、配置审计、可复现研究、技术文档和故障定位。

## 输入

- 当前 `main`：`25b920c964b5d67603386db20acc87fdbeed5f97`。
- `docs` 中各版方案、Phase 2 报告、现有环境和 golden 数据。
- Jetson Orin Nano Super 与本地 Qwen3-1.7B（若历史模型仍存在）。
- 上一份架构调查报告。

## 执行步骤

1. 生成完整 inventory：文件、目录、语言、非空/占位、入口、配置、结果、测试和文档 Claim。
2. 建立 Claim Ledger。每个“已完成/性能数字”标记为 `source-only`、`test-verified`、`runtime-verified`、`historical-unreproduced` 或 `planned`。
3. 核对 Phase 2 报告列出的 `hqsb/models`、`scripts/models`、结果目录和环境文件；从可信历史机器/备份恢复，无法恢复则明确删除完成声明。
4. 恢复 `hqsb.models.loader`，限定职责为 artifact 校验、tokenizer/model 加载、device/dtype/attention 配置、资源释放和结构化错误。
5. 恢复模型下载、hash、manifest、verify、smoke 脚本；下载与 benchmark 严格分离。
6. 修复当前入口的 import、路径、参数和失败退出行为；不得依赖未文档化的 `PYTHONPATH`。
7. 核对四份 golden 数据来源、模型/tokenizer hash 和 schema；无法证明来源的数据标为 legacy，不进入回归门禁。
8. 在 Jetson 重新运行 device query、最小 RMSNorm 和最小 Qwen smoke；保留完整命令、环境和 raw output。
9. 更新 README 状态矩阵，区分 Implemented/Verified/Experimental/Planned。
10. 建立 `docs/project_status.md` 与 `docs/evidence_ledger.md`，将旧方案保留为历史而非当前事实。
11. 对恢复的文件做秘密、绝对路径、个人信息和大模型制品检查。
12. 提交一个职责单一的恢复 Commit，并记录迁移说明。

## 输出与产出

- 可导入、可执行的最小 Python 模型链路。
- CUDA device/RMSNorm 与 model-core smoke 的 raw evidence。
- `project_status.md`、Evidence Ledger、恢复/删除清单。
- 更新后的 README 当前状态和最小运行命令。
- S00 handoff：Commit、环境、已知缺口和 S01 输入。

## 测试标准

- 静态：Python/C++/CUDA 文件能被相应 parser/compiler 发现，无悬空 import。
- CPU：配置、manifest、hash 和 CLI 参数的最小测试。
- Jetson：device query 非零设备、RMSNorm correctness PASS、Qwen tiny workload 生成指定数量 token。
- 负向：模型文件缺失、hash 不符、CUDA 不可用和非法参数均返回可诊断的非零退出。

## 验收通过标准

- 新 clone 按 README 可以在目标环境复现三条 smoke 路径。
- 当前文档没有无法由 Git tree 或明确 artifact 解释的“已完成”声明。
- 每个历史性能数字都有证据路径；无证据者已降级为 historical claim。
- 仓库工作树无秘密、大模型权重和机器专属绝对路径进入默认配置。

## 明确不做

不优化性能、不增加新模型/后端、不改造整体目录；只恢复事实和最小执行闭环。

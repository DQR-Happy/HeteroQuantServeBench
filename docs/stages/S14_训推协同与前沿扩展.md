# S14：训推协同与前沿扩展

## 阶段目标

在不破坏推理/算子主线的前提下，建立分布式训练、后训练/RL rollout、多模态、稀疏注意力、投机解码和 Agent Infra 等相邻岗位能力的实验区。

## 体现的知识与技能

Megatron/DeepSpeed/FSDP、SFT/DPO/RLHF/GRPO、veRL/Slime/OpenRLHF、训推一致性、VLM/Diffusion/Audio、稀疏/线性注意力、Agent/workflow。

## 输入

- 稳定的 S01 Contract、S07 Runtime、S08 Serving、S10 Distributed、S13 Infra。
- 独立 `experimental` 配置和资源；不得成为主包默认依赖。

## 执行步骤

1. 建立训练技术地图：DDP/FSDP/ZeRO、TP/PP/EP、activation checkpoint、mixed precision、checkpoint 和容错。
2. 使用小模型完成 Megatron/DeepSpeed/FSDP 中至少一个训练 smoke，记录显存、吞吐和通信。
3. 建立训推 artifact/precision/tokenizer 一致性检查，验证 checkpoint 到 serving 的转换。
4. 搭建最小 SFT/DPO 或 GRPO rollout 链；分离 trainer、inference engine、environment、reward 和 data。
5. 研究异步 rollout、batching、KV reuse、staleness 和 on-policy consistency；接 vLLM/SGLang。
6. 实验 speculative decoding/MTP：draft/target、acceptance、quality、latency 和 cost。
7. 实验 structured sparsity、sparse/linear attention 或 Test-time Scaling 中至少一项。
8. 选择一个多模态 workload：VLM、Diffusion/DiT 或 Audio；分析其算子、显存和调度差异。
9. 为 Agent Infra 建立异步 workflow、tool call、memory/evaluation/trace 的最小 workload，用作 Serving 压测而非取代 Kernel 研究。
10. 评估端侧 Android/ARM/TFLite/MNN/NCNN/QNN 或机器人实时系统，形成技术地图/可选 adapter。
11. 所有实验通过 feature flag/optional dependency 隔离，并输出是否值得进入主线的 ADR。

## 输出与产出

- `experimental` 训练/RL/multimodal/speculative configs 与报告。
- 一条小型训推/rollout 闭环和一致性检查。
- 一个前沿推理算法与一个多模态 workload 的性能分析。
- Agent/edge 技术地图与主线采纳 ADR。

## 测试标准

- 训练 checkpoint 与推理输出一致性；随机 seed 和版本可追溯。
- RL/rollout 的数据、策略版本、reward 和 failure 可追踪。
- 投机解码质量不退化，报告 acceptance 和额外计算。
- Optional dependency 不污染核心安装和 CI。

## 验收通过标准

- 至少一个训练/RL 和一个前沿推理实验有源码、数据和结论。
- 能解释为何某能力进入或不进入生产主线。
- 不以浅层框架调用冲淡 S03–S10 的核心技术深度。

# S06：框架集成与图优化

## 阶段目标

把 S03–S05 的算子和量化能力安全接入 PyTorch 模型，建立 Custom Op、Dispatcher、FX/Inductor 图重写、Meta/FakeTensor 和 fallback，使优化不再停留在 standalone microbenchmark。

## 体现的知识与技能

PyTorch dispatcher/ATen、C++/CUDA extension、`torch.library`、Autograd、FX、Dynamo/Inductor、图模式匹配、动态 shape、ABI 和内存管理。

## 输入

- S01 Contract/registry/test。
- S03 CUDA、S04 Triton/CUTLASS、S05 Quant kernels。
- S02 Qwen reference 和固定 workload/golden。

## 执行步骤

1. 设计 binding boundary：Python API、C++ OperatorSpec、device/stream、workspace、lifetime、错误映射。
2. 注册 CPU reference、CUDA、Meta/FakeTensor 实现；明确 inference-only 或 backward 支持。
3. 实现 shape/dtype/layout/device validation 和 capability query；不支持时 deterministic fallback。
4. 为 RMSNorm/第二热点建立模块替换，不修改模型权重语义。
5. 建立 FX pattern：例如 residual+RMSNorm、RMSNorm+Quantize 或 RoPE 子图；检查 alias、side effect 和动态 shape。
6. 接入 TorchDynamo/Inductor：记录 graph break、compiled graph、generated Triton/C++ 和 cache key。
7. 对 eager/reference/custom/fused/compiled 路径做 operator、block、model 三层 differential test。
8. 检查 stream、allocator、CUDA Graph capture、autocast 和 mixed precision 行为。
9. 测量 Python/C++ dispatch、compile、cache warmup、kernel 和端到端开销。
10. 对 unsupported shape、版本不匹配、编译失败建立 fallback、warning 和 telemetry。
11. 建立 ABI/PyTorch/CUDA 版本矩阵和构建 artifact。
12. 输出图前后可视化、性能数据和收益归因。

## 输出与产出

- `cpp/bindings`、Python Custom Op package、Meta/FakeTensor。
- FX/Inductor rewrite 与 capability/fallback。
- Model-level integration tests、graph snapshots 和 performance report。
- 版本兼容矩阵与安装 artifact。

## 测试标准

- 模块替换前后 token/logit/hidden state 一致性。
- Dynamic/unsupported shape、contiguous/non-contiguous、不同 stream/device。
- Graph break 数量、compile cache、recompile 和 fallback 测试。
- 无内存泄漏、悬空引用、隐式同步和重复分配。
- Micro speedup 与 model speedup 同时报告。

## 验收通过标准

- 至少两个 operator/一个 fusion 可在真实 Qwen 模型启用、关闭和回退。
- 端到端结果通过 correctness gate，性能变化可解释。
- 另一个模型或 backend 能通过 Contract 复用，而非硬编码 Qwen 类名。

# S10：分布式推理与通信

## 阶段目标

建立拓扑感知的多 GPU/NPU 推理与通信实验层，覆盖 TP/PP/CP/EP、Collective、通信计算重叠、MoE Dispatch/Combine 和弱互联性能分析。

## 体现的知识与技能

分布式系统、模型并行、NCCL/HCCL/RCCL、MPI/UCX/NVSHMEM、NVLink/PCIe/RDMA/RoCE/InfiniBand、collective 算法和 overlap。

## 输入

- S07 Runtime/backend 与 S08 serving trace。
- S01 distributed config/result/event contract。
- 至少双 GPU；Ascend 多卡用于 HCCL 分支。

## 执行步骤

1. 采集 topology：GPU/NPU、NUMA、PCIe、NVLink/NVSwitch、NIC/RDMA；生成机器可读 manifest。
2. 建立 collective microbench：AllReduce、AllGather、ReduceScatter、AllToAll、Broadcast，不同 size/rank/algorithm。
3. 建立带宽/延迟模型，比较 ring/tree/hierarchical，计算 bus bandwidth 与算法效率。
4. 实现 Runtime 的 TP 最小路径，记录权重切分、激活、KV 和 collective 次数/字节。
5. 扩展 PP/CP/SP 的最小实验，比较 bubble、通信和显存。
6. 针对 MoE 建立 EP、expert placement、AllToAll 和 Dispatch/Combine；可接 DeepEP 类实现。
7. 使用 stream/event 分离计算和通信，设计 baseline/no-overlap/overlap；验证依赖正确性。
8. 使用 nsys/NCCL traces/msprof 分析 collective 与 kernel timeline、CPU launch 和网络瓶颈。
9. 研究 NCCL/HCCL/RCCL、MPI/UCX/NVSHMEM 的层次和适用场景；可选 GPUDirect/IBGDA。
10. 将 topology-aware placement/routing 接入 serving/distributed config。
11. 故障实验：rank failure、timeout、网络退化、拓扑不对称和 OOM；记录恢复边界。
12. 运行单卡/多卡 strong/weak scaling，报告 latency、throughput、efficiency、memory 和 cost。

## 输出与产出

- `hqsb/distributed` topology、parallel plan、collective adapter。
- Collective microbenchmark、TP/EP runtime experiment。
- Communication/computation overlap profile 和 scaling report。
- 弱互联、拓扑与故障 runbook。

## 测试标准

- Collective 数值正确、rank 顺序、不同 message size 和 dtype。
- Parallel 与单卡 reference 的 token/logit 对齐。
- Overlap 模式无竞态、死锁、隐式全局同步。
- 超时和 rank failure 有明确失败，不无限挂起。

## 验收通过标准

- 至少 TP + 一种 collective 形成端到端闭环；MoE 路径至少完成 micro/runtime 之一。
- 能用消息量、拓扑和 profile 解释 scaling efficiency。
- 至少一个通信计算 overlap 优化有可重复数据。

# S13：生产化、云原生与可靠性

## 阶段目标

把 HQSB 从单机实验转化为可部署、可观测、可扩缩、可恢复的 AI Serving 系统，验证容器、调度、模型制品、容量和性能回归的生产工程能力。

## 体现的知识与技能

Docker/containerd、Kubernetes、Ray/Slurm/Volcano、CI/CD、资源调度、存储、SRE、监控、eBPF、容量与成本。

## 输入

- S08 Serving、S10 Distributed、S12 workload/capacity data。
- Container registry、Kubernetes/Ray 或等价测试环境。
- ModelArtifact 与 release artifact。

## 执行步骤

1. 建立分层容器镜像：base/toolchain/runtime/model-independent；锁定 digest、SBOM 和漏洞扫描。
2. 实现设备发现和 capability label；GPU/NPU 资源请求、affinity、NUMA/topology 和隔离。
3. 建立 Kubernetes/Helm 或 Ray Serve 部署；配置 readiness/liveness/startup、graceful termination。
4. 实现模型制品下载、校验、本地 cache、预热、版本切换和回滚；模型不打进通用镜像。
5. 建立 autoscaling：queue/token/concurrency/GPU utilization/SLO 信号，避免只用 CPU。
6. 实现容量规划和 admission：模型内存、KV Cache、batch/token budget 与节点容量。
7. 接入 Prometheus/Grafana、logs/traces、GPU/DCGM/Ascend metrics 和告警。
8. 使用 perf/eBPF/ftrace/网络指标定位系统层瓶颈；与 request trace 关联。
9. 故障注入：pod/node/backend/cache/storage/network，测试重试、降级、恢复和数据一致性。
10. 运行 rolling/canary upgrade 和性能回归 gate；失败自动回滚。
11. 评估对象/分布式存储、Lustre/GPFS/JuiceFS、Redis/Kafka 等在模型/KV/事件中的边界。
12. 输出 SLO、on-call runbook、capacity/cost report 和 disaster recovery 边界。

## 输出与产出

- `infra/containers`、deployment/Helm、observability 和 CI/CD。
- Model artifact cache/lifecycle、autoscaling/admission policy。
- Dashboard、alerts、fault injection 与 recovery report。
- Production runbook、capacity 和 cost model。

## 测试标准

- 镜像重建、digest/SBOM、秘密不进入镜像。
- 部署/滚动升级/回滚、模型 cache 校验、cold/warm start。
- 过载、节点故障、网络/存储抖动、OOM 和慢客户端。
- Autoscaling 不造成振荡，SLO/成本指标有稳定测试。

## 验收通过标准

- 从空集群部署到可服务有自动化流程；单节点故障可恢复或明确降级。
- 监控能回答请求、模型、backend、GPU/NPU 和系统层原因。
- 发布有性能 gate、canary 和回滚，不依赖手工判断。

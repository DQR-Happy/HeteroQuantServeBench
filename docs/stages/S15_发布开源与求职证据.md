# S15：发布、开源与求职证据

## 阶段目标

把全部技术工作转化为可信的开源项目、技术报告、演示和可验证求职证据，确保招聘者能快速看到深度、广度、个人判断和真实结果。

## 体现的知识与技能

技术写作、架构表达、实验报告、开源协作、代码审查、Release、演示、STAR 项目叙事和研究诚信。

## 输入

- S00–S14 的源码、tests、results、profiles、ADR、handoff 和 limitations。
- 招聘能力总表与岗位方向。

## 执行步骤

1. 清理当前状态：支持矩阵、known issues、planned 与 experimental，禁止文档过度声明。
2. 编写中英文 README：问题、架构、quick start、结果、复现、limitations、roadmap。
3. 生成架构图、数据流、优化闭环、Runtime/KV、分布式拓扑和部署图；与代码一致。
4. 整理核心报告：Baseline/Profile、CUDA、Triton/CUTLASS、Quant、Runtime/Serving、Ascend、Distributed、Compiler、Cross-hardware。
5. 建立 benchmark dashboard/静态图；所有图链接 raw artifact、config 和 Commit。
6. 发布版本化 model-independent artifacts、容器、schema、sample results 和 checksums。
7. 准备 3–5 分钟 demo：从一条命令到 profile/optimization/result；预录并提供脚本。
8. 准备 3/10/30 分钟讲述：目标、架构、最难问题、失败假设、数据、个人贡献、限制和下一步。
9. 为每个岗位能力建立 Evidence Index：文件、测试、报告、图和可回答问题。
10. 生成简历 bullet 候选，但性能数字仅从 verified result 自动填入，禁止占位或虚构。
11. 选择 PyTorch/Triton/vLLM/SGLang/CANN 等上游提交至少一个高质量 Issue/PR/文档贡献。
12. 进行外部 review：让另一 Coding Agent 仅按 README 复现，让审阅者挑战 correctness、benchmark 和架构。
13. 做秘密/license/model license/第三方 attribution 检查。
14. 发布 release、changelog、roadmap 和可复现 artifact；保留审计记录。

## 输出与产出

- 中英文 README、文档站/报告集、架构与性能图。
- Release artifact、container、checksums、reproduction guide。
- Demo 视频/脚本、Evidence Index、面试问答和简历素材。
- 上游 Issue/PR 与外部复现报告。

## 测试标准

- 干净环境按照 quick start 可复现 sample；链接、命令和 schema 自动检查。
- Dashboard 数字与 raw artifact 一致。
- 安全、license、secret、模型权重和个人路径检查。
- 文档支持矩阵与自动 capability/test 状态一致。

## 验收通过标准

- 招聘者可在 5 分钟内理解项目，在 30 分钟内审计关键结论。
- 每个核心技能至少有一条真实 Evidence；所有性能数字可复现。
- 能清楚区分本人设计判断、Coding Agent 产出和第三方框架能力。
- 至少一次外部复现和一次真实开源协作完成。

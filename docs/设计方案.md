## 结论

**这些硬件足够完成一个有深度的 `HeteroQuantServeBench`，而且你的组合比单纯租一张高端GPU更适合做“异构部署”项目。**

但项目目标需要重新定义：

> 不是强行让“所有量化算法×所有模型×所有后端”全部跑通，而是建立一套**量化算法、模型表示、底层算子、推理后端、服务系统和Benchmark相互解耦的异构推理工程平台**。

你的设备应这样分工：

-   **Jetson Orin Nano Super**：CUDA C++、GPU Profiling、TensorRT/llama.cpp、端侧推理、功耗与内存优化。
    
-   **Orange Pi AI Pro 20T**：CANN、Ascend C、torch\_npu/MindSpore/MindIE、国产NPU模型适配、精度对齐和算子开发。
    
-   **租用3090/4090**：x86 CUDA、Triton、vLLM/SGLang、量化模型生成和中等规模Benchmark。
    
-   **A100**：只作为可选验证环境，不作为主要开发环境。
    
-   **5090**：本项目没有必要专门租，除非价格与4090接近且软件环境已经准备好。
    

Jetson Orin Nano Super拥有8GB统一内存、102GB/s内存带宽、1024个CUDA Core和67 TOPS稀疏INT8算力，NVIDIA也明确展示了INT4量化的1B—8B模型在该设备上的运行能力。它非常适合端侧LLM、CUDA Kernel和性能工程，但不适合承担大规模模型训练或重型并发服务。([NVIDIA Developer](https://developer.nvidia.com/blog/?p=93942 "NVIDIA Jetson Orin Nano Developer Kit Gets a “Super” Boost | NVIDIA Technical Blog"))

Orange Pi AI Pro 20T采用昇腾技术路线，提供20 TOPS INT8算力及12GB/24GB两种内存版本，支持Ubuntu和openEuler。你的具体内存容量会影响模型范围：12GB建议以0.5B/1.5B为主；24GB可以尝试更多3B和量化7B模型。([Orange Pi](https://www.orangepi.org/html/hardWare/computerAndMicrocontrollers/details/Orange-Pi-AIpro%2820t%29.html?utm_source=chatgpt.com "Orange Pi - Orangepi"))

# 五、量化算法设计

## 1\. 不要直接声称“支持所有量化方法”

更专业的表述是：

> 通过插件接口支持不同量化算法，并针对不同推理后端记录其可部署性、数值精度和运行性能。

量化算法分成四层。

### 第一层：基础方法

必须自己实现：

-   FP16/BF16基线；
    
-   INT8 RTN；
    
-   INT4 RTN；
    
-   Per-tensor；
    
-   Per-channel；
    
-   Per-group；
    
-   对称与非对称量化。
    

这部分证明你理解：

-   Scale；
    
-   Zero Point；
    
-   Clipping；
    
-   Group Size；
    
-   Quantize/Dequantize；
    
-   量化误差。
    

### 第二层：主流工程方法

至少选择三种：

-   GPTQ；
    
-   AWQ；
    
-   SmoothQuant；
    
-   可选HQQ或其他方法。
    

你可以调用官方或社区实现，但必须统一测评流程，不能只执行命令。

### 第三层：论文复现插件

把你正在复现的最新论文方法做成统一接口：

```python
class Quantizer(ABC):
    @abstractmethod
    def calibrate(
        self,
        model: torch.nn.Module,
        calibration_data: Iterable,
    ) -> QuantState:
        ...

    @abstractmethod
    def quantize(
        self,
        model: torch.nn.Module,
        state: QuantState,
    ) -> QuantizedArtifact:
        ...

    @abstractmethod
    def export(
        self,
        artifact: QuantizedArtifact,
        target: BackendTarget,
    ) -> ExportResult:
        ...
```

论文复现价值来自：

-   没有官方代码时你独立实现；
    
-   与论文结果进行误差分析；
    
-   解释无法复现部分；
    
-   增加不同模型和硬件测试；
    
-   给出部署可行性。
    

仅“实现了公式”价值有限。必须继续做：

-   Ablation；
    
-   Calibration样本敏感性；
    
-   Group Size；
    
-   不同层敏感性；
    
-   精度—速度—显存关系；
    
-   后端可部署性分析。
    

### 第四层：后端原生格式

不同后端可能支持不同格式：

-   GGUF；
    
-   GPTQ/AWQ；
    
-   TensorRT量化格式；
    
-   ONNX QDQ；
    
-   CANN/MindIE支持的量化格式。
    

必须将“算法量化”和“后端打包”分开。

# 七、CUDA算子库设计

## 第一阶段算子

依次完成：

1.  Vector Add，用于验证编译和测试框架；
    
2.  Reduction；
    
3.  Softmax；
    
4.  RMSNorm；
    
5.  RoPE；
    
6.  SwiGLU；
    
7.  Fused RMSNorm＋Quantize；
    
8.  可选INT4 Dequantize＋MatVec。
    

不要先做完整FlashAttention。它复杂度太高，容易拖垮项目。

## 每个算子至少包含四个版本

```text
reference/
    pytorch_reference.py

cuda/
    naive.cu
    optimized.cu

triton/
    kernel.py

tests/
    test_correctness.py
    test_edge_cases.py

benchmarks/
    benchmark_shapes.py
```

Triton可以主要在租赁的x86 GPU上完成；Jetson承担原生CUDA C++版本。

## 优化路线

以RMSNorm为例：

### V0：Naive Kernel

-   每个线程处理一个元素；
    
-   全局内存中间结果；
    
-   不做向量化。
    

### V1：Block Reduction

-   一个Block处理一行；
    
-   Shared Memory归约；
    
-   减少Kernel数量。
    

### V2：Warp Shuffle

-   使用warp-level reduction；
    
-   减少Shared Memory同步。
    

### V3：Vectorized Load

-   `half2`、`float4`等；
    
-   保证地址对齐；
    
-   合并访存。
    

### V4：融合

-   RMSNorm＋Quantize；
    
-   RMSNorm＋Residual；
    
-   或RMSNorm＋RoPE的可行子路径。
    

## 必须测量

-   Latency；
    
-   Effective Bandwidth；
    
-   Occupancy；
    
-   Register Usage；
    
-   DRAM Throughput；
    
-   L2 Hit Rate；
    
-   Warp Stall原因；
    
-   数值误差。
    

Jetson端运行：

```bash
sudo nvpmodel -m 2
sudo jetson_clocks

nsys profile \
  --output reports/nsys/rmsnorm \
  ./build/bench_rmsnorm

ncu \
  --set full \
  --export reports/ncu/rmsnorm \
  ./build/bench_rmsnorm
```

NVIDIA官方说明Super性能模式通过新的功耗配置提高GPU、CPU和内存频率；正式Benchmark时应锁定功耗模式、散热条件和环境温度，并把这些信息写进报告。([NVIDIA Developer](https://developer.nvidia.com/blog/?p=93942 "NVIDIA Jetson Orin Nano Developer Kit Gets a “Super” Boost | NVIDIA Technical Blog"))

# 十八、最重要的范围控制

你当前最大的风险不是硬件不足，而是项目范围失控。

-   数十种模型；
    
-   数十种量化算法；

-   完整AI编译器；
    
-   NCCL通信库；
    
-   Kubernetes集群调度器；
    
-   大规模RAG；
    
-   前端聊天产品。
    

第一版优先级必须是：

1.  **跨后端量化和精度体系；**
    
2.  **CUDA＋Ascend C同功能算子；**
    
3.  **统一Serving接口；**
    
4.  **完整Benchmark；**
    
5.  **工程质量与文档。**
    

NCCL不需要独立增加到这个项目中。条件允许时，用双GPU租赁环境补充一个NCCL AllReduce Microbenchmark和TP推理分析即可。AI编译器也不需要单独新建完整项目，先在本项目中加入一个FX图重写或自定义融合Pass，已经能够证明你具备计算图和编译优化意识。

按照这个设计，你手里的两块板卡不是妥协，而是项目最有辨识度的核心：**同一个模型和算子，在CUDA边缘GPU、国产NPU和数据中心GPU上的算法、软件栈、精度、性能与工程差异**，正是大量异构计算和国产算力岗位希望候选人真正理解的内容。

## Known limitations

- Compute Sanitizer is not a pass; it remains blocked by the target's GPU
  debugging configuration.
- Historical S00-E05-02 experiments were not regenerated on the unified tree.
- No non-Jetson CUDA architecture was available for a live replay. The
  cross-architecture contract is covered by code/tests, not by a second GPU.
- The integration is deliberately uncommitted. `git status` is the review
  boundary until the user creates the timestamp-controlled commit.

## Workflow after review

1. Disable bidirectional/upload-on-save SFTP for repository source. Use Git as
   the source transport and keep a separate clean Jetson run clone per branch.
2. Make source changes on a named feature/experiment branch. Before any run,
   record the exact commit; if the tree must be dirty, also save `git diff
   --binary`, the untracked-file inventory, and their hashes.
3. Pull evidence one way from Jetson into an append-only evidence area. Never
   push with `--delete` into `docs/stage_experiments` or `reports`.
4. Give every experiment run a manifest containing source commit, dirty-patch
   digest, hardware/software fingerprint, command, and raw-output digests.
5. Treat `scripts/sync_to_jetson.sh` only as a scoped compatibility tool. It
   excludes `.git`, builds, third-party dependencies, caches, and evidence and
   intentionally does not delete remote files. Prefer `git fetch` plus an
   explicit branch/worktree for routine development.

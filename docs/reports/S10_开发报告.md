## 1. 阶段目的与核心证据（从文档推导）

### 1.1 实质性目的

`docs/stage_experiments/README.md` §2 对 S10 的一句话定位是「**解释多卡扩展效率**」，
`details/S10/README.md` §1 把完整证据链写成：

```text
相同 ModelArtifact / precision / tokenized WorkloadSpec
  → 可机器读取的物理拓扑与 rank placement
  → 经过正确性验证的 collective 基线
  → 版本化 ParallelPlan 与权重/KV shard
  → 单卡 reference ↔ 多 rank tensor/logit/token 对齐
  → 理论通信账本 ↔ 实际 collective event/bytes
  → compute / communication / wait / idle critical path
  → strong/weak/capacity scaling
  → no-overlap ↔ overlap 的因果验证
  → straggler/链路/故障定位与有界恢复
  → S11/S12 可重放的 raw、trace、profile 与限制
```

阶段核心命题（同文档 §1 末）：**多卡执行必须保持单卡模型语义；扩展收益必须由计算、通信、
等待和拓扑证据解释；故障不能无限挂起。**

### 1.2 进入 S11/S12 时必须交出的核心证据（S10 实验清单 §"阶段完成标志"）

1. E10-01~E10-06、E10-08~E10-10 通过（E10-07 仅当声称 PP/CP/SP 时才要求）；
2. 至少 TP + 一种 collective 构成模型端到端闭环，token/logit 与单卡 reference 对齐；
3. collective message-size 曲线、通信量模型与 strong/weak scaling；报告 compute/communication/idle 三分解；
4. 至少一个 overlap 优化有可重复正/负结论，timeline 能证明重叠而非计时错觉；
5. rank failure/timeout/OOM 不会无限挂起，communicator、进程和显存可回收；
6. E10-08 至少完成 MoE collective micro 或 Runtime 路径（完整 MoE/EP 声明另有门）。

**本轮的交付边界**：上述每一项都是"实验结论"，因此本阶段**只交付产出它们所需的全部能力**，
不产出结论本身（见 §8）。

### 4.3 communicator 安全与故障 oracle（E10-03 / E10-10）

from hqsb.distributed import faults as ft, sequence as sq

machine = sq.CommunicatorStateMachine("tp")
machine.transition("READY"); machine.begin_collective(0); machine.complete()
machine.fail("dtype mismatch")
try:
    machine.begin_collective(1)                # 错误后复用 → 结构化拒绝
except Exception as exc:

                             maximum_global_abort_time_s=10.0)

## 6. 关键设计决策与权衡

1. **分层层级**（§2）：L0 基础设施 → L1 通信语义 → L2 模型/性能 → L3 证据/脚手架，依赖只向下。
2. **CPU 可导入性**：全部 20 个模块无模块级 `torch`/`triton`/`numpy`（AST 扫描 + 子进程探针双重固定）；
   NCCL/HCCL/torch.distributed 一律函数内惰性探测并给结构化 reason。
3. **不产结论的默认态**：`RunDirectory.write_verdict` 需要 (allow_execute ∧ 前置满足 ∧ raw samples>0)
   三者同时成立才写 PASS/FAIL/PASS_NEGATIVE；否则一律降级为 `BLOCKED` 并写原因。
4. **前置门不自解锁**：证据路径只接受 `docs/stage_experiments/S10/**`；脚手架写入
   `experiment_results/` 的指纹不计入（回归测试固定该行为）。
5. **模拟必须自证是模拟**：`LoopbackCollectiveExecutor` / `LoopbackResult.claim_allowed()` 恒 False；
   `LoopbackResult.as_dict()` 带 `simulated=True` 与"非设备测量"说明。
6. **公式 ID 化**：带宽/拟合公式全部登记 ID，结果行携带 ID；vendor 原生列与派生列在结构上分开。
7. **区间集合而非时长求和**：overlap 由 `merge_intervals` + 交集测度计算，杜绝并发 kernel 重复计时。
8. **不伪造 T1**：无单卡基线时只给 `speedup_from_p0`，并把"不得称强扩展效率"写进返回 note。
9. **缺失格不补零**：`ResourceMatrixCell.as_row()` 对不可用格返回 `MISSING` + `None` + reason。
10. **故障"正确失败"的定义机器化**：`evaluate_fault()` 把 E10-03 §12 的 8 类作弊式通过写成断言。
11. **MoE skew 生成器去退化**：zipf 权重绑定到**打乱后的 expert 顺序**，避免所有 zipf profile
    都退化成"全部打给 expert 0"（实测发现并修复，见 §7 自检第 6 条）。
12. **错误目录数据驱动**：`classify_distributed_error` 只返回目录内已登记条目，未登记一律 UNKNOWN + reason。

被否决的替代方案见 `S10_parallelism_design.md` §6（ADR-S10-01 ~ ADR-S10-08）。

5. `calibrate_offsets` 未记录校准时间 → 补齐 `measured_before/after`（时钟不确定性必须有时间窗）；

7. `snapshot_delta` 把"仅 allocator cache 增长"误分类为 `reclaimed` → 区分 cache/leak/reclaimed；
8. `_matmul` 用具尺寸不匹配时抛裸 `IndexError` → 改为结构化 `ConfigError`；
9. 账本原因码目录与代码常量不一致（缺 3 个）→ 补齐并加回归断言。

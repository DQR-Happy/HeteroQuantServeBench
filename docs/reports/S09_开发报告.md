## 6. 关键设计决策与权衡

1. **分层（details README §6）**：compatibility/capability/probes ← tiling/operators/test_vectors/sim_device ← backend/framework/quant_format/model_core/profiling/comparison/faults/mapping ← telemetry/specs/experiment/interface_map，依赖只向下。理由：E09-02~E09-10 复用同一 TilingData ABI 和算子 spec，capability 表独立于具体实现。

2. **CPU 最小化可导入**：`hqsb/ascend` 在模块级不 import `torch`/`torch_npu`/`triton`/`numpy`（依赖边界测试 + gate R8/R9 拦截）。理由：Ascend 后端必须能在 CPU-only 环境中安装和测试契约层，硬件适配器通过 lazy import 或 `NOT_AVAILABLE` 原因处理。

3. **CPU 测试双模拟设备**：`sim_device.py` 是纯 Python 实现的 Ascend 执行模型代理，用于验证 TilingData ABI 的自洽性（host↔device 解析一致）、tail 处理、multi-core 划分、guard/poison 检测。它被明确标记为模拟（`claim_allowed() = False`），never produce real device numbers。

4. **UB 模型选择器**：`TilingRequest.ub_model` 显式声明使用哪个 UB 成本模型（rmsnorm/reduce/elementwise），避免 reduction 候选被错误地按 rmsnorm 计费（带 gamma）。这保证了 E09-04 的 UB 预算计算准确。

5. **loop_units 逻辑**：行向算子（rowwise=True）的 loop_count 基于 hidden，平铺算子（rowwise=False）基于 per_core_elems。这解决了 Add 在多核下的 tile 计数问题。

6. **防止自我解锁**：前置门只读 `docs/stage_experiments/S09/**`；脚手架写入 `experiment_results/` 的指纹不计入（回归测试 `test_prerequisites_do_not_self_unlock`）。理由：与 S06/S07/S08 关闭同一陷阱。

7. **错误目录数据驱动**：拒绝路径只能返回目录内已登记的 code/status/retryability，未登记的错误码在分类时显式报错（负向测试覆盖）。理由：防止「把永久错误伪造成 500、把过载伪造成入参错误」。

8. **四态能力而非布尔值**：SUPPORTED_VERIFIED/SUPPORTED_UNVERIFIED/UNSUPPORTED/UNKNOWN + NON_GOAL scope。UNKNOWN never authorises execution，必须携带 missing probe reason。理由：E09-01 §4.4 明确要求四态，防止猜测性支持。

9. **容忍度按 (operator, dtype) 唯一**：`ToleranceSpec` 没有 backend 字段，同一对不能有两个不同的 gate。理由：E09-03 §6/§11 "不为 Ascend 放宽阈值" 是结构约束而非审查。

10. **禁止静默降级**：任何 fallback 必须记录 requested/actual/reason，且 `SimResult.claim_allowed() = False` 确保模拟结果不被误用。

被否决的替代方案：直接依赖某个具体推理引擎 SDK（违反模块 ownership 与 CPU-minimal 约束）；把 SLO 门限硬编码在代码（无法审计预注册状态）；把路由评分与硬过滤合并成一个加权和（会选出「高分但不兼容」的后端）。

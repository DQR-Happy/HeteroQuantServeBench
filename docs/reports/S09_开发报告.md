## 2. 当前真实实现边界

已存在且可测试的是：

- compatibility manifest、redaction、field diff；
- capability 四态；
- read-only probes 与 fixture executor；
- TilingData ABI、checked arithmetic、UB 静态模型；
- Add/Reduction/RMSNorm CPU oracle、共同 tolerance 与 test vectors；
- 明确不可用于声明的 CPU simulated device；
- 本轮新增的实验协议、证据采集、逐步状态和前端索引。

尚不存在或不可宣称已实现的是：

- `backend.py`、`framework.py`、`quant_format.py`、`model_core.py`、`profiling.py`、`comparison.py`、`faults.py`、`mapping.py`、`telemetry.py`、`specs.py` 等旧报告列出的数据面模块；
- 可编译/可运行的 Ascend C Add、Reduction、RMSNorm 内核；现有 `.cpp/.h` 仍是占位源码；
- torch_npu/aclnn/ATB/MindIE 框架接入；
- 真实 Qwen Ascend model-core、msprof、低精度 kernel、跨硬件 benchmark 和真实故障恢复。

因此，旧版“30+ 模块就位”“代码层验收通过”“Backend Adapter source exists”等表述均撤销。本轮只把协议编排和真实阻塞证据补全，不把规划接口写成实现事实。

## 5. 设计约束

1. collector exit code 与 scientific verdict 分离；
2. 缺设备/工具链时只写 `BLOCKED`，不生成空壳性能行；
3. CPU smoke 始终 `simulated=true`、`claim_allowed=false`；
4. E09-06 只有显式低比特声明才激活；
5. E09-09 缺第二真实 backend 时必须 `NOT_RUN_ON_SECOND_BACKEND`；
6. run 身份同时绑定 Git 状态、全 S09 source tree、OperatorSpec 与 compatibility manifest；
7. 重采前自动归档旧 raw，不覆盖历史事实；
8. 前端只读原 verdict，不提升或重写科学状态。

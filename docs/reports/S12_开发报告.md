## 1. 阶段目的与核心证据（从文档推导）

### 1.1 实质性目的

`docs/stage_experiments/S12_实验清单.md` 的首句：

> S12 不再开发某个后端，而是回答：**在给定业务 workload、质量和 SLO 下，哪种硬件/
> 精度/Runtime 更合适，结论是否公平、可审计？** 禁止用单一峰值或不透明总分代替决策。

`details/S12/README.md` §3 把十个实验串成闭环（先证明能比，再证明能跑；先产 raw，
再做归一化；先量化稳定性，再解释机理；先分别算性能/能耗/成本/成熟度，再按业务约束构造
Pareto）。

### 1.2 进入 S13 时必须交出的核心证据（S12 实验清单 §"阶段完成标志"）

1. E12-01 至 E12-10 全部通过；
2. 至少三类硬件，或两类硬件加两种架构，形成通过质量门的有效同协议对比；
3. 每个结论同时覆盖性能、质量、内存/能耗、成本、软件限制和置信度；
4. 不可比项显式留空并解释；所有 dashboard/图能回溯和重生成；
5. 能为至少三个业务画像输出不同的 Pareto 部署建议；
6. 若缺少价格/功耗可靠来源，只能完成性能选型，不能声称 TCO/能效结论。

**本轮的交付边界**：上述每一项都是"实验结论"，因此本阶段**只交付产出它们所需的全部能力**，
不产出结论本身（见 §8）。

### 4.1 可比性裁决与非法 join 防护（E12-01）

```python
from hqsb.evaluation import comparability as cmp
from hqsb.evaluation.contracts import default_contract, NormalizationFormula

contract = default_contract()
policy = cmp.FieldClassificationPolicy()
audit = cmp.run_audit(
    [
        {"cell_id": "c1", "comparison_id": contract.comparison_id, "candidate_id": "cand_a",
         "layer": contract.workload.layer, "scenario": contract.workload.scenario,
         "workload_spec_id": contract.workload.workload_spec_id,
         "measurement_contract_id": "mc1", "quality_gate_id": contract.quality.gate_id,
         "actual_backend": "cuda"},
    ],
    contract, policy=policy,
)
print(audit.verdict_histogram())          # 四态直方图
# 非法 join：跨 contract / 跨 layer / quality fail / missing 都会被拒绝并给稳定错误码
decision = cmp.illegal_join_guard(
    [{"cell_id": "c1", "comparison_group_id": "g", "comparability_status": "NOT_COMPARABLE",
      "quality_status": "pass", "actual_backend": "cuda"}],
    allowed_group_ids={"g"}, contract_by_group={"g": contract},
)
print([row["error_code"] for row in decision.rejected])
```

## 6. 关键设计决策与权衡

见 `S12_cross_hardware_design.md` §3（9 项决策，含理由与被否决替代方案）。要点：

1. **四态可比性，非布尔**；`CONDITIONAL` 无公式即降级 `NOT_COMPARABLE`。
2. **缺失是状态不是零**：10 类 `MISSINGNESS_CODES`，`numeric_value` 对 missing 抛错。
3. **能量 total 与 incremental 同报**、不同 boundary 不同排序。
4. **成本无内置价格**；价格快照是 dated 输入 artifact。
5. **peak 只算乐观偏差**，不得当容量分母。
6. **成熟度三合法路径**，永不合成总分。
7. **lineage raw append-only**；fault injection 必须定位到实体与下游 claim。
8. **决策回归套件标注 algorithm_regression**（合成数据，非实验）。
9. **目录约定**：`artifacts/S12/` 逻辑布局落到 `experiment_results/S12/`（仓库既有约定）。

自检过程中发现并修复的**真实缺陷**（不是测试让步）：

1. `convert_unit` 误把 `_UNIT_CANONICAL`（字符串）当数值乘 → 改为 scale 乘除，raw 值保留；
2. `dependency_order` 只访问请求集内的依赖 → 改为总是递归传递依赖（probe plan 不再建立在未验证前置上）；
3. `CapabilityMatrix.record` 只拦截"覆盖成 NONE" → 改为按等级顺序拒绝弱化覆盖；
4. `invalidation_key` 是不可读的纯 hash → 改为 `field=hash` 列表，失效触发可定位到具体字段；
5. `evaluate_negative_probes` 的 `ok` 返回列表而非 bool → 改为 `bool(rows) and all(...)`；
6. `quantile` 最近秩实现使偶数样本中位数偏小 → 改为 R-7 线性插值（中位数=中点，p95 不塌缩到最大值）；
7. `uncertainty_budget` 把 resolution 既当分量又当阈值（循环）→ 改为 half-width 与 resolution 比较；
8. `_resolve` 不识别 dataclass 字段引用 → 支持 `__dataclass_fields__`；
9. `write_verdict` 把 `BLOCKED` 当结论状态被"execution disabled"覆盖 → 只门禁 `PASS/PASS_NEGATIVE/FAIL`；
10. 两个测试文件与既有 `test_capability.py`/`test_roofline.py` 同名导致 pytest 收集冲突 → 改名 `test_eval_*.py`。

## 1. 阶段目的与核心证据（从文档推导）

### 1.1 实质性目的

S15 不再验证代码本身，而验证整个项目作为**公开技术制品**的可审计性（`S15_实验清单.md` §阶段实质性目的）：

> 一个不了解内部历史的招聘者或开发者，能否快速理解价值并独立复现关键结论？

`details/S15/README.md` §1 将其写成一个乘积式主命题：

```text
public project credibility =
    claim truthfulness × artifact identity/provenance × executable documentation
  × clean-environment repeatability × independent reproducibility
  × figure-to-raw lineage × release security/licensing
  × failure-transparent demonstration × defensible communication
  × public collaboration evidence
```

任一乘项缺失都必须降低公开声明等级——不能靠"文件很多/README 名词多/release 有二进制/作者机器上 demo 跑通一次/简历写了个 speedup"来替代。

### 1.2 进入下一阶段时必须交出的核心证据

S15 没有传统意义上的"下一技术阶段"（`details/S15/README.md` §4：下游是公开发布与求职使用），
因此它的"完成标志"是 §25.2 的最终验收清单：

- E15-01～E15-10 全部 PASS；E15-11 投递前建议 PASS；
- 至少一个 hero story + 两个深入子故事；
- clean CPU quickstart 有真实 session、目标 GPU/NPU hero replay 有真实新环境数据；
- 至少一个独立 reviewer 完成核心复现、至少一个真实公开上游贡献达到质量门；

## 6. 关键设计决策与权衡

1. **新建 `hqsb/release` 区域，而不是并入 `hqsb.infra`**：infra 是"生产化/云原生/可靠性"（S13，
   供应链接口已有 SBOM/秘密/provenance 词汇表），release 是"发布/开源/求职证据"（S15）。
   语义重叠只在 E15-05 的供应链，但 S15 全层只依赖 `core`，以 record/digest/manifest 描述资产，
   不与 infra 共享对象（避免环：R17 禁止下层反向依赖）。
2. **四重门**：S14 是三重门（--execute + 前置 + raw samples），S15 追加"必须绑定 release candidate
   + claim ledger digest"。理由：S15 的每条公开 claim 若不指向冻结候选，本身就是 orphan。
3. **stable claim id 用事实签名而非文案**：`stable_claim_id` 对 `FACT_SIGNATURE_FIELDS` 求 digest，
   措辞微调不动 id、改变 scope/baseline 才动 id——直接落实 `E15-01` step 13/45。
4. **detector 必须有负对照**：所有扫描器（claim/link/command/figure/secret）的 `PASS` 都要求
   `negative_control_metrics`，漏检 P0 注入时 `clean_result_valid=False`（`telemetry.DetectorMetrics`）。
5. **"SKIP 不是最终状态"**：`docs_gate` 的命令验收状态拒绝 `SKIP`，GPU 命令在 CPU 上是
   `BLOCKED_DEVICE` 并需 owner/失效日期——直接落实 `E15-04` §9.1。
6. **冻结词汇表是生成物 + 漂移检查**：与 S13/S14 一致，`configs/release/*.yaml` 由
   `gen_release_specs.py` 生成，`--check` 重渲染 diff；`specs.py` 拒绝测量值/绝对路径/未知键。

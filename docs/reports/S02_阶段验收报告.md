### 2.1 细节

- `WorkloadSpec(input_tokens=0)` → `ValidationError`（token ≥ 1）；
- `make_fixed_token_input` 内 `assert input_ids.shape[1] == input_tokens`；
- YAML `workloads` 非法条目 → `ConfigError`（`test_workload_config.py`）。

### 2.2 细节

- `compare_token_sequence` 在序列不等时返回 `first_mismatch_index`、
  `actual_token`、`expected_token`（`test_correctness.py::test_first_mismatch_localized`）；
- `verify_determinism` 记录 `distinct_sequence_hashes`（=1 则确定）；
- `compare_against_golden` 要求 `schema_version` 并聚合 token + logits 对比。

### 2.3 细节

`benchmark_model_core` 每个阶段（prefill forward、first-token argmax、每个
decode step）前后均 `torch.cuda.synchronize()`，`time.perf_counter()` 界定，
异步 kernel launch 不会被误计为完成。

### 3.1 结果可追溯性

`run_s02_baseline.py` 为每个 workload 产出 `BenchmarkResult`，其中：
- `model_artifact_hash`：由 manifest 的 14 个文件 SHA256 计算；
- `config_hash`：由 workload 规范化 JSON 计算；
- `environment`：platform/device/compute_capability/python/torch/cuda/框架版本；
- `git_commit`/`git_dirty`：运行时采集；
- `raw_samples`：每个 repetition 的逐 token 原始 ITL。

### 3.2 Hotspot 硬件证据

`reports/dev/profiler/s02/hotspot_summary.json`（真实 CUDA profiler，sudo +
`perf_event_paranoid=0`）：

- **Decode-heavy**：`aten::mm` 39.9% + `ampere_fp16_s16816gemm` 28.4% +
  `ampere_fp16_s16816gemm_128x64` 8.1% + cutlass 1.3% ≈ **78% GEMM**；
- **Prefill-heavy**：`aten::mm` 24.9% + cutlass 12.5% + 4.9% ≈ **48% GEMM**，
  elementwise（copy_/mul）≈ 35–40%。

### 3.3 S03 决策（来自 Profile）

> GEMM 主导 decode（78%）与 prefill 最大类（48%）。不从头写 GEMM，改用
> CUTLASS/低比特(int4/int8) GEMM + epilogue fusion；RMSNorm 作为 elementwise/
> reduction 教学闭环；融合 aten::copy_/mul/cat 削减 launch/sync。

stop criteria：候选需给出 correctness（对比 golden/reference）、performance
（shape 矩阵加速比）、stop（退化 shape 检测）三要素，见 `optimization_log.md`
模板。

## 1. 阶段目的与核心证据（从文档推导）

可观测性」，并最终用 **服务级严格 A/B（E08-11）** 证明某一次策略改动的因果收益。

3. 到达过程（恒定/泊松/突发）对队列与尾延迟的敏感度（E08-03）；
4. 混合负载/优先级/多租户的公平性与 HOL 饥饿（E08-04）；
5. 准入/令牌预算/背压/过载拒绝与恢复（E08-05）；
6. 多后端 capability/SLO 路由（E08-06）；

8. 慢读/断连/批量取消/优雅停机的流生命周期（E08-08）；
9. 故障注入/熔断器/恢复时间线（E08-09）；
10. 端到端可观测性（metrics/logs/traces/profiles 同源）（E08-10）；

## 6. 关键设计决策与权衡

1. **分层（details README §6）**：协议平面 / 网关平面 / 策略平面 / 后端平面（S07
   契约）/ 证据平面，依赖只向下。理由：E08-02~E08-11 复用同一协议/网关，策略与
   证据可独立替换与测量。
2. **纯 Python 服务核心**：`hqsb/serving` 在模块级不 import `torch`/`triton`/`numpy`
   /`ops`（依赖边界测试 + gate R5/R6 拦截）。理由：服务平面必须 CPU-minimal 可导入；
   后端通过 S07 稳定契约（`BackendSession`/`ServingBackend`）注入。
3. **无模型夹具 `dummy_backend`**：协议、SSE、错误映射的证明不依赖模型（E08-01
   step 3、E08-09 step 2）；`claim_allowed()` 恒 False，防止被当作真实后端。
4. **SLO 模板默认拒绝评估**：`preregistration_status != frozen` 时 `require_frozen`
   抛错、`max_slo_goodput` 返回 `NOT_EVALUATED`。理由：门限是策略不是结果，不得
   事后移动（E08-02 §11）。
5. **防止自我解锁**：前置门只读 `docs/stage_experiments/S08/**`；脚手架写入
   `experiment_results/` 的指纹**不计入**（回归测试
   `test_prerequisites_do_not_self_unlock`）。理由：与 S06/S07 关闭同一陷阱。
6. **复用 S07 统计口径与门禁**：`service_ab.py` 复用 `hqsb.runtime.policy_ab`
   （SelectionGate/Adr/measure_ab/causal_chain/regression/pilot/rollback），
   `slo.py` 复用 `hqsb.benchmark.metrics.percentile`。理由：阶段间统计定义唯一。
7. **错误目录数据驱动**：拒绝路径只能返回目录内已登记的 code/status/retryability，
   未登记的错误码在分类时显式报错（负向测试覆盖）。理由：防止「把永久错误伪造成
   500、把过载伪造成入参错误」。

被否决的替代方案：直接依赖某个具体推理引擎 SDK（违反模块 ownership 与
CPU-minimal 约束）；把 SLO 门限硬编码在代码（无法审计预注册状态）；把路由评分与
硬过滤合并成一个加权和（会选出「高分但不兼容」的后端）。

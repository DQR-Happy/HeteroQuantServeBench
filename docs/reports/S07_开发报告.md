## 1. 总体目标

按 `docs/stage_experiments/details/S07/README.md` §1，本阶段要证明 HQSB 已从
「调用模型 forward」进入「管理多个请求执行状态」的 Runtime 层：

```
Backend Contract → request admission/state → scheduler iteration → token budget/batch
  → KV block allocation/prefix reuse → model runner → attention/kernel/graph
  → sampling/output → cancel/finish/free → C6/C7 evidence
```

**本次交付的边界**（遵循任务约束「提供接口，但不执行实验」）：

- **已交付**：E07-01 ~ E07-10 全部 **200 个实验步骤**所依赖的能力、函数、
  数据结构、驱动入口与支撑模块；以代码 + **460 个新增测试**证明其成立。
- **未交付（实验层）**：任何正式实验执行，以及任何 TTFT/TPOT/TPS/容量/碎片/
  命中率/降低显存/加速比数字。原因见 §9。

## 4. 逐模块说明（含可直接复制的调用示例）

### 4.1 请求语义与 capability 协商（`request.py`）

```python
from hqsb.runtime import request as R

identity = R.ModelIdentity(model_id="Qwen/Qwen3-1.7B", model_manifest_sha256="a"*64,
                           revision="rev-1", tokenizer_id="Qwen/Qwen3-1.7B",
                           chat_template_hash="tpl", precision="float16")
spec = R.RequestSpec(request_id="r0", identity=identity, input_token_ids=tuple(range(32)),
                     sampling=R.SamplingSpec(mode="greedy"), stop=R.StopSpec(max_new_tokens=8))

cap = R.CapabilityReport(backend_id="vllm")
cap.declare("model_artifact", "SUPPORTED_EXACT")
cap.declare("prefix_cache", "UNSUPPORTED_REJECT", reason="KV backend disabled by policy")
resolved = R.resolve_request(spec, cap)          # 未声明的字段一律按 UNKNOWN 处理
resolved.changed_parameters()                    # 只列出「requested != actual」且带 reason 的项
R.assert_single_primary([backend_spec_reference, backend_spec_cloud])   # 只允许一个主 runtime
```

关键契约：任何 `requested != actual` 必须带 reason（`ResolvedConfig.record` 直接拒绝）；
`EMULATED` 必须给测量的成本说明；`UNKNOWN` 默认拒绝相关 claim。

### 4.2 Adapter 七类操作与诚实探测（`adapter.py`）

```python
from hqsb.runtime import adapter as A

probes = A.probe_environment()                 # find_spec；不 import 引擎
A.select_primary_engine(probes)                # 无唯一可用引擎 → ok=False + reason
dummy = A.DummyRuntimeAdapter(backend_spec)    # 契约夹具；performance_claim_allowed() 恒 False
A.run_load_close_scenarios(lambda: A.DummyRuntimeAdapter(backend_spec))  # 6 个生命周期场景
```

`load` 返回的实际身份必须与冻结身份一致（`verify_identity`），否则 `BackendError`——
「自动选到另一个 revision」在设计上不可表达。

### 4.4 Trace、账本与 hot path（`trace.py`）

```python
from hqsb.runtime import trace as T

machine = T.RequestStateMachine("r0")
machine.transition(T.RequestState.VALIDATED); machine.transition(T.RequestState.WAITING)
# ... ADMITTED → PREFILLING → DECODING → FINISHED → CLEANED
machine.require_clean_finish()                 # 非终态 / 取消后再 admit 会抛 SchemaError

collector = T.SpanCollector(run_id="run-1")
```

### 4.5 KV 几何、生命周期与容量（`kv.py`）

```python
from hqsb.runtime import kv

geometry = kv.KVGeometry(num_layers=28, num_kv_heads=8, head_dim=128, element_bytes=2)
geometry.bytes_per_token                        # 114688.0（含量化侧数据时为 payload + 侧数据）
pool = kv.BlockPool(total_blocks=8, block_size=16)
blocks = pool.allocate("r0", token_start=0, token_count=40)
pool.share(blocks[-1], "r1"); pool.mark_cached(blocks[-1], "r0"); pool.release("r0")
pool.invariant_report()["ok"]                   # free/refcount/readers 一致性
pool.inject_double_free("r0")                   # → DOUBLE_FREE_ABSORBED（不污染 pool）
pool.evict(blocks[0]); pool.inject_stale_id_access(blocks[0])   # → STALE_ID_REJECTED

recon = kv.MemoryReconciliation(geometry=geometry, block_size=16, active_tokens=64,
                                tolerance_bytes=1024.0)
recon.declare("block_table_metadata", 512.0)     # 未命名类别 → ConfigError
recon.measured_framework_reserved = recon.predicted_total_bytes + 100
recon.explained()                                # 残差超容差 → False（不允许叫「碎片」）

kv.find_capacity_boundary(lambda tokens: tokens <= 921, low=1, high=4096)  # 确定性二分
kv.oom_action("execution_oom", 0)                # 每条 kind 一条有限阶梯，末尾必为 reject/fail
```

## 7. 关键 bug 修复与决策记录

1. **前置门自我解锁风险**（§2.3）：指纹只认协议树；新增回归测试。
2. **调度器的 token 守恒缺口**：prefill 完成当轮会同时产生 1 个 decode token，
   原实现只增加 `scheduled` 不增加 `computed`，导致
   `previous + scheduled - rollback != new`（实测 residual=+1）。
   修复后逐轮断言守恒，随机 trace 属性测试固定该不变量。
3. **admission 预留语义**：原实现按 `computed` 计账，长 prompt 会先过度接纳再反复
   preempt。改为 `admission_reserve_full_isl=true` 时按 `prompt + max_new` 预留 block
   （E07-03 步骤 13 / E07-04 步骤 13 的明确要求），并用测试固定「3 blocks 容量时
   `max_concurrent_running <= 1`」。
4. **OOM 阶梯**：原实现用单一全局动作序，`predictable_admission_reject` 永远返回
   `reject`、无法终止序列。改为**每个 kind 一条有限阶梯**且必然以终态动作
   （`reject`/`fail`）结束；`max_oom_attempts` 与 `configs/runtime/kv_spec.yaml`
   逐字段审计一致。
5. **Prefix cache key 与 digest 不一致**：`canonical()` 原先只覆盖 identity 字段，
   导致 `parent_chain_digest`/`block_token_sequence_hash` 变化不改变 digest。
   修复为覆盖全部 key 字段 + 内容摘要，并把负向 fixture 改为**在 key 上变异**
   （原先在 identity dict 上变异，对不读取该 dict 的字段等于没变）。
6. **多 KV group 命中取交集**：原实现只对「有命中的 group」取最小值，单组命中会被
   虚报成全模型命中。改为对**全部被请求的 group**取最小值（缺失组按 0 计）。
7. **伪造碰撞政策**：`strong_digest` 与 `digest_plus_token_equality` 之前没有行为差异。
   现在前者只比 digest，后者在 digest 相等但 token 不等时拒绝并计数，
   并新增对照报告「digest-only 政策会服务伪造记录」。
8. **`token_denominator_audit` 不判负**：原实现只记录 delta 不产生 problem。
   现在超出容差即 fail（含相对容差），避免「自报 TPS 与 raw 不一致却通过审计」。
9. **`two_factor_analysis` 的符号依赖字母序**：`sorted()` 会把 `cuda_graph` 排在
   `eager` 前，导致主效应符号随命名翻转。改为**保留调用方声明顺序**并显式定义
   `graph_effect = cuda_graph − eager`、`attention_effect = candidate − default`。
10. **claim 门的理由质量**：证据不完整时原先会被 spec 的 `claim_cuda_graph=false`
    抢先覆盖，报告里看不到缺哪一项。现在先报缺失项，再由 spec 决定是否声称。
11. **`specs.make_comparison_spec` 缺身份**：原先抛 `TypeError`，现在抛
    `ConfigError` 并列出缺失字段（checked-in 的占位 hash 等于伪造身份）。
12. **测试文件重名冲突**：`tests/unit/runtime/test_import_boundaries.py` 与
    `tests/unit/integration/` 下同名文件在无 `__init__.py` 的测试目录下冲突，
    已重命名为 `test_runtime_import_boundaries.py`。
